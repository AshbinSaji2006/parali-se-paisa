# Dataset inventory and reproduction

This repository combines public-source geospatial observations, derived research products, and clearly marked synthetic demo fixtures. The data included in Git is a compact, reproducible subset; large local copies remain on the machine that acquired them and are not removed by this policy.

Exact paths and byte sizes for excluded bulk assets are recorded in [`DATASET_MANIFEST.json`](DATASET_MANIFEST.json). The acquisition-time source metadata, hashes, and coverage notes are in [`data/real/DATASET_MANIFEST.json`](data/real/DATASET_MANIFEST.json) and [`data/real/DATASET_MANIFEST.md`](data/real/DATASET_MANIFEST.md).

## Large assets kept locally

The raw Sentinel-2 and Sentinel-1 GeoTIFF stacks, multi-year full-field time-series Parquet files, full GeoJSON copy of the field boundaries, raw FIRMS archives, and country-wide geoBoundaries cache are reproducible bulk data. They are excluded from Git to keep clones manageable. Their exact local paths and sizes are in `DATASET_MANIFEST.json`; this does not delete or move them.

Git LFS is used for six retained research Parquet assets above 10 MiB (about 121 MiB total); their exact patterns are in `.gitattributes`. It is not used for the reproducible raw archives. [GitHub recommends repositories below 1 GB and blocks ordinary Git files larger than 100 MiB](https://docs.github.com/en/repositories/creating-and-managing-repositories/repository-limits); [LFS has separate storage and bandwidth quotas](https://docs.github.com/en/billing/concepts/product-billing/git-lfs). The 9.3 GiB of raw scenes and full time-series data are better reacquired from providers than embedded into this prototype’s clone. All files selected for ordinary Git are kept below 50 MiB.

## Rebuild products

From the repository root, install the Python dependencies and use the acquisition commands above. For a full current-season refresh, `python scripts/update_live_2026.py` downloads or reuses current Sentinel-2/FIRMS context and rebuilds the research products and deck. This requires network access and can be limited by provider availability or credentials. `python scripts/build_real_products.py` rebuilds the compact application products from already acquired inputs; `python scripts/validate_real_data.py` writes the validation report.

The current app snapshot contains 520 sampled research fields and 3,640 Sentinel-2 field-date observations; it is not the full 243,530-polygon research population. The project reports `NO_MODEL` because independent field-status ground truth is not available. Derived weak labels are not validation truth.
