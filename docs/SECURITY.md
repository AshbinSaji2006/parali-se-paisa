# Security model

The API uses Argon2id password hashes and 30-minute HS256 JWTs with issuer, audience, issue time, expiry and token ID claims. The API reloads the active user record on requests and applies default-deny role checks. OFFICIAL/ADMIN users can operate the dashboard. Operators see jobs assigned to their baler and can only request valid backend state transitions. Buyers see their buyer record and allocated loads. Farmers see their own field, its history, verification and certificates, and can submit eligible pickup requests. SQLAlchemy loader criteria enforce record ownership as well as endpoint permissions.

Demo accounts are inserted only by `scripts/seed_accounts.py` or the documented reset/demo commands. Passwords come from environment values or a cryptographically generated value saved to the ignored `.demo/credentials.json`; no default login is embedded in production code. Demo accounts cannot sign in when `DEMO_MODE=false`. In a demo process without an explicit `JWT_SECRET`, the API creates a random in-memory key and reports that fact; restarting invalidates those tokens. A non-demo process requires a 32-character `JWT_SECRET`.

`CORS_ORIGINS` is an explicit origin allowlist. Wildcards are rejected. Requests receive a correlation ID and basic security headers. Authentication failure logs omit usernames, passwords, token values and request bodies. A small per-process login throttle complements, but does not replace, reverse-proxy rate limiting for a multi-worker production deployment. Certificate files are restricted to the generated certificate directory. Public integrity reports recompute the metadata SHA-256; this is not a digital signature or a hash of the PDF bytes.

Live mode filters all synthetic field, buyer, baler, verification and job rows, blocks demo users and refuses operational writes while verified sources are unavailable. This protects the no-provider state; production deployment still requires TLS termination, secret management, an external shared rate limiter, operational monitoring, reviewed provider ingestion and a security review.
